# CNL-P — a format for documents an agent has to read precisely

Unpacked from `cnlp-kit.zip`, generated by ai-factory-adr-extension __VERSION__.

## Where to put it

The archive has 2 entries and takes 2 moves:

- **`cnlp/`** — everything the kit brings. Copy the whole folder to the root of your project.
  Delete it when the migration is over and the root is exactly as it was.
- **`cnlp-migrate/`** — the skill that does the work. Move it into whichever agent runs it:
  `.claude/skills/` for Claude Code, its own skills directory for Codex. An agent with no
  skill mechanism reads the file by path instead: "read `cnlp-migrate/SKILL.md` and follow
  it". The body is the instruction; a slash command is only a shortcut to it.

Nothing else is scattered at the root.

## What is inside `cnlp/`

| File | What it is | Who owns it |
|---|---|---|
| `cnlp-format.md` | the standard: forms, line rules, lexicon, the profile contract | upstream — re-unpack to update |
| `profiles/profile.md` | the profile of a profile | upstream |
| `cnlp.js` | the checker: node builtins only, no dependencies | upstream |
| `skill-format.test.js` | runs the checker over your skills | upstream |
| `profiles/skill.md` | the skill profile: generic spine, empty vocabulary | **you** |
| `quality-rules.md` | a rubric to prune, not a standard | **you** |

Re-unpacking overwrites the upstream 4 and would overwrite your 2 as well, so commit your
`profiles/skill.md` and `quality-rules.md` before you do it.

## Order of work

1. **Read `cnlp/cnlp-format.md`.** Nothing below makes sense before it, and it is the file the
   migration keeps referring to.
2. **Run `cnlp-migrate`.** Its first phase is an inventory: every top-level `key:` your
   existing skills already use, mapped onto blocks. That is what fills `custom_sections:` in
   `cnlp/profiles/skill.md`. The profile is authored before any skill body is touched.
3. **Let it migrate a single skill end to end**, then read the diff before the rest follows.
4. **Prune `cnlp/quality-rules.md`** and copy the variant a skill needs into its
   `quality_rules:` block, verbatim. Lines marked `[adr]` name artifacts you probably do not
   have.

## Running the check

```
node --test cnlp/skill-format.test.js
```

Set `SKILLS_DIR` at the top of that file to where **your** skills live, relative to the
project root — it names the corpus to check, and it has nothing to do with where you moved
`cnlp-migrate`. The check refuses to run with a clear message when the directory is missing.

**No Node in this repository?** Delete `cnlp/cnlp.js` and `cnlp/skill-format.test.js`, and set
`enforcement:` in `cnlp/profiles/skill.md` to say the profile is held by review against the
standard. The rest works unchanged — the checker is a convenience, the standard is the
authority. It has no dependencies, so adding `node --test` later costs nothing but the files
you deleted.

## What deliberately did not come along

- `transitions:` and `status_footer:` — lifecycle conventions of the project this came from.
  Add them to `cnlp/profiles/skill.md` only if your skills have the same conventions.
- its 24 `custom_sections` names — that vocabulary is about architecture decision records,
  plans and review lenses. Yours comes from the inventory in step 2.
